\# Frappe CRM Backup Automation



\## About the Project



This project is a Python-based backup automation tool developed for Frappe CRM as part of my DevOps internship task.



The main idea behind this project is to automate the backup process instead of manually running backup commands every time. It uses Frappe Bench commands to create backups and Python to handle file management, checksum verification, retention and restore operations.



I have also tested the restore process using a separate test site (`crm-test.localhost`) so that the original CRM site is not affected.



\## Features



\- \*\*Automated Backup:\*\* Creates a Frappe Bench backup containing the database, public files and private files.

\- \*\*Site Configuration Backup:\*\* Keeps a separate copy of the site configuration backup generated by Bench.

\- \*\*SHA-256 Verification:\*\* Generates checksums for backup files and verifies their integrity.

\- \*\*Retention Policy:\*\* Keeps the latest 7 backup folders and removes older ones.

\- \*\*Restore:\*\* Restores the database and files into a separate test site.

\- \*\*Logging:\*\* Maintains a log of backup operations and errors.

\- \*\*Command Line Interface:\*\* Supports backup, verification, listing and restore operations.

\## How to Use



All commands should be executed from the main project directory.



\### 1. Create a Backup



```bash

python backup-automation/backup\_tool.py backup

```



This runs the Frappe Bench backup command and copies the generated backup files into a timestamped folder inside `backup-automation/backups/`.



Each backup contains:



\- Database backup (`.sql.gz`)

\- Public files archive (`.tar`)

\- Private files archive (`.tar`)

\- Site configuration backup (`.json`)



\### 2. Verify Backup Integrity



```bash

python backup-automation/backup\_tool.py verify --folder 20261105\_153556

```



The tool calculates SHA-256 hashes and compares them with the saved checksum file.



If the files match, they are displayed as VERIFIED.



\### 3. List Available Backups



```bash

python backup-automation/backup\_tool.py list

```



This displays the available backup folders.



\### 4. Restore a Backup



```bash

python backup-automation/backup\_tool.py restore --folder 20261105\_153556

```



The restore operation uses a separate test site named `crm-test.localhost`.



The script checks whether the test site already exists before attempting to create it. It does not overwrite an existing test site.



A MariaDB compatibility issue with the `NOTE\_VERBOSITY` SQL setting was encountered during testing. To handle this, the restore process creates a temporary compatible copy of the SQL backup before importing it. The original backup remains unchanged.



\*\*Note:\*\* The test site should not already exist when running the automated restore command.



\### 5. Test the Retention Policy



```bash

python backup-automation/backup\_tool.py retention-test

```



This creates temporary test backup folders and checks whether the retention policy keeps only the latest seven.

\## Security and Backup Handling



Actual database backups, private files, site configuration backups, logs and Python cache files are excluded from Git using `.gitignore`.



The site configuration backup may contain sensitive information, so it should not be pushed to a public repository.



The restore process keeps the test site's own configuration instead of replacing it with the original site's configuration.
